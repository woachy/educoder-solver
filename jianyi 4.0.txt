# 头歌自动答题系统 v4.0 优化建议复盘

> 注：头歌平台服务器网络波动为偶发事件，网络波动/服务器错误相关的重试与改动在此次规划中忽略。

## 一、 核心痛点与缺陷分析

### 1. 智能控速（Pacing）跨进程状态丢失 (P0)
- **现状**：
  工具设计初衷是为了防教师端作弊审查，内置了 `min-duration 60` 秒拟真思考，配合 5~20 秒随机浮动。
  但开题打卡时间戳（`_task_start_times`）保存在 Python 进程的内存字典里。
- **缺陷**：
  在短连接 CLI 模式下（AI Agent 先后执行 `open-task` 与 `solve-cycle`），每个命令都是独立的 Python 进程。`solve-cycle` 启动时读不到上次的开题时间戳，误以为刚刚开题，导致每道题都强行等待满额的 60s+ 拟真倒计时（长达 75s+），造成大量无意义等待。
- **建议方案**：
  将关卡开题时间写入本地缓存（如 `.cache/pacing_state.json`），实现跨 CLI 进程的真正差额补足；同时在本地排障或快速测试时支持显式传入 `--min-duration 0`。

### 2. 代码注入未真正触发 React SPA 状态变更与 Git 提交保存 (P0)
- **现状**：
  `inject_code` 原先仅调用了 Monaco 的 `models[0].setValue(val)`。
- **缺陷**：
  头歌现代前端是基于 React 的 SPA，仅修改 Monaco 编辑器底层 Model 内存**不会同步更新 React 组件的 State**，更不会向后端发送保存请求。
  点击“评测”按钮时，头歌后端评测容器拉取到的依然是云端未修改的代码（空文件或初始模板），导致回执显示“实际输出为空”或测试失败。
- **建议方案**：
  在注入代码后，必须穿透 React Fiber / 编辑器实例，显式调用 `ed.onChange(val)` 与 `ed.onSave(1)`，或模拟快捷键与触发真实 Input/Change 事件，确保平台向后端发送 Save 请求并获取 `commitID`，确认保存成功后再触发评测。

### 3. 课堂作业页面层级未自动穿透 (跳板页阻断) (P1)
- **现状**：
  在班级作业列表页点击“开始学习”后，头歌部分大题并没有直接打开编程工作台，而是打开了一个中间大题详情页（`/detail?tabs=1`），需要再次点击“开始实训”或“继续挑战”才进入实训 IDE。
- **缺陷**：
  `open-task` 第一次抓到了详情页后即认为完成，短连接 AI 必须二次执行 `open-task --match detail` 寻找按钮，流程割裂且极易超时。
- **建议方案**：
  在 `open_classroom_task` 内部增加自动穿透逻辑：若检测到落脚点是 `/detail?tabs=` 页面，自动检测并点击“开始实训/继续挑战”跳入真正的编程关卡页面，实现一步直达。

### 4. 编辑器探查对 `window.Monaco` / 自定义类名大小写与全局函数兼容 (P1)
- **现状**：
  部分头歌实训打包机制将 Monaco 挂载在全局 `window.Monaco`（首字母大写）或通过 `window.updateMonacoValue` 同步，且容器类名可能为 `.my-monaco-editor`。
- **建议方案**：
  规范化 Monaco 检测链路，支持 `window.monaco || window.Monaco`，支持 `.monaco-editor, .my-monaco-editor`，并在更新代码后调用 `window.updateMonacoValue`（若存在）。

---

## 二、 忽略项说明
- **头歌服务器网络波动与下载超时**：头歌沙箱评测集群在从其后端 Git 仓库拉取学生代码时偶发报“当前网络较差，代码下载超时，请稍后重试！”，经确认属服务器端偶发故障，本次优化规划予以忽略，不额外增加复杂的服务器网络波动熔断重试逻辑。
